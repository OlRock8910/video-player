# PC BUILDER

**Build. Power. Perform.**

A 3D PC-building simulator for Android. You physically open a case, place
standoffs, seat a motherboard, align a CPU, click memory into its slots, screw
down a graphics card, route cables, and press the power button — then watch the
machine boot, POST, and benchmark.

Not a menu-based configurator: the loop is
**pick up → rotate → position → install → screw/connect → admire → power on →
test → earn money → build better PCs.**

---

## Running it

```bash
npm install
npm run dev          # http://localhost:5173
```

Other scripts:

| Command | What it does |
| --- | --- |
| `npm run build` | Typecheck, then produce the web bundle in `dist/` |
| `npm test` | Unit tests for the simulation engine |
| `npm run typecheck` | TypeScript only |
| `npm run preview` | Serve the built bundle on :4173 |
| `node tests/playthrough.mjs --shots` | Drive a full build in a real browser and screenshot it |

The playthrough test needs the preview server running first.

## Building the Android APK

The native Android project is committed at `android/`, generated by Capacitor
and then configured for a game (portrait, hardware accelerated, no `INTERNET`
permission — the game is entirely offline).

### With a local Android SDK

```bash
npm install
npm run android:sync         # vite build + npx cap sync android
cd android
./gradlew assembleDebug      # → android/app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease    # → android/app/build/outputs/apk/release/app-release.apk
```

Requires JDK 21 and the Android SDK (compileSdk 34, minSdk 22). Set
`ANDROID_HOME`, or open the `android/` folder in Android Studio via
`npm run android:open`.

### With CI

`.github/workflows/android.yml` runs the typecheck, unit tests and browser
playthrough, then builds both APKs and uploads them as the `pc-builder-apk`
artifact. Push the branch, open the run, and download the APK from there — no
local Android toolchain needed.

> The release APK is signed with the debug keystore so CI produces something
> installable. Add a real keystore and a `signingConfigs.release` block in
> `android/app/build.gradle` before publishing anywhere.

## How it is put together

```
src/
├── data/            Pure content. Adding hardware means editing these files only.
│   ├── types.ts       Component schema — every part's shape lives here
│   ├── brands.ts      Fictional manufacturers and their accent colours
│   ├── career.ts      Customers, jobs, reputation, challenges, achievements
│   └── catalog/       Cases, CPUs, motherboards, GPUs, and the rest
├── sim/             Headless rules. No Three.js, no DOM — all unit tested.
│   ├── Build.ts               The build model and its state machine
│   ├── CompatibilityManager   What fits, what does not, and why
│   ├── PowerManager           Wattage estimate and PSU recommendation
│   ├── ThermalManager         Temperatures, airflow and noise
│   ├── CableManager           Cable-management scoring
│   ├── BenchmarkManager       Scores, grades and fictional game FPS
│   ├── PostManager            POST results and troubleshooting checklists
│   └── BuildSteps.ts          The ordered build pipeline
├── scene/           Three.js. Procedural geometry, no downloaded assets.
│   ├── PartBuilders   Every component's mesh, sized from its catalog data
│   ├── CaseLayout     Slot anchors derived from the chassis dimensions
│   ├── BuildScene     Installs, screws, panel, cables, power state
│   ├── CameraController / InteractionManager
│   ├── RGBManager / CableRenderer / Materials
│   └── SceneRoot      Renderer, lighting, workbench, frame loop
├── core/            GameManager, SaveManager, Settings, Audio, Haptics, EventBus
└── ui/              Screens and the design system
```

### Design rules the code follows

**Data-driven parts.** Adding a GPU is one entry in
`src/data/catalog/gpus.ts`. Its length feeds case-clearance checks *and* the 3D
model's size, its power feeds the PSU maths, its cooling feeds the thermal
model. No other file changes.

**Simulation is separable.** Everything in `src/sim/` is plain TypeScript over
plain data, which is why it can be covered by fast unit tests and why the same
rules drive the shop badges, the install checks and the final report.

**Blockers vs. warnings.** Physically impossible builds are refused — wrong
socket, GPU too long, cooler too tall, radiator that will not fit. Merely
*unwise* builds are allowed with a warning, and the consequences arrive at
benchmark time. Ignore the PSU warning and the machine can fail under load.

**No assets to download.** Meshes are procedural, sounds are synthesised with
the Web Audio API, fonts are platform stacks. The APK works with the device in
aeroplane mode, and there is no loading beyond parsing the bundle.

**Nothing teleports.** Parts animate from wherever the player released them into
the slot. Screws rotate and sink while held. The side panel slides off.

## What is in the vertical slice

Workbench, case with a removable side panel, standoffs, motherboard, CPU with
orientation checking, thermal paste, air/tower/AIO cooling, memory with notch
alignment, M.2 and SATA storage, PSU with modular cables, GPU, case fans with
per-fan airflow direction, cable routing and ties, the compatibility engine,
power/thermal/noise models, the power-on cinematic, POST, troubleshooting
diagnostics, the animated benchmark, build grading, showcase mode, career with
customers and reputation, the parts shop, the garage, challenges, achievements,
RGB customisation, graphics presets with dynamic resolution, haptics,
accessibility options, and autosave.

## Controls

| Gesture | Action |
| --- | --- |
| One finger drag | Orbit the camera |
| Two-finger pinch | Zoom |
| Two-finger drag | Pan |
| Double tap | Focus on what you tapped |
| Tap | Select a part and see what it is |
| Tap a part in the tray | Pick it up |
| Drag | Carry the held part to its slot |
| Press and hold a screw | Drive or back it out |
| Tap an installed fan | Flip its airflow direction |

## Developer mode

Turn on **Settings → Developer mode** for an FPS/draw-call overlay and a
`window.pcb` console API:

```js
pcb.addMoney(5000)      pcb.unlockAll()        pcb.completeBuild()
pcb.testPost()          pcb.testBenchmark()    pcb.forceError('no-display')
pcb.spawn('gpu-ps-t9')  pcb.listComponents()   pcb.resetBuild()
```

## Not real hardware

Every brand, product and benchmark title is invented. CoreForge, PixelStorm,
NexaChip and the rest are not references to real companies, and the performance
figures are game balance, not measurements.
